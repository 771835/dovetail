# 调试指南

## 第零步：冷静

编译器给你报了错。先别急着改代码，先看看错误信息说了什么。

Dovetail 的错误信息通常包含：错误类型、错误位置（文件名+行号）、具体描述，
有时候还会附上一条"建议"——虽然那建议偶尔是在劝你换语言，但大部分时候还是有用的。

错误信息分为五大类，先搞清楚你遇到的是哪一类：

| 错误类型                 | 含义                     | 谁的锅                       |
|--------------------------|--------------------------|------------------------------|
| 语法错误 (0x1xxx)        | 源代码结构不符合语言规范 | 你的                         |
| 语义错误 (0x2xxx~0x5xxx) | 代码逻辑不符合语义规则   | 你的                         |
| 内部错误 (0x6xxx~0x7xxx) | 编译器内部逻辑异常       | 编译器的                     |
| 运行时错误 (0x8xxx)      | 后端代码生成阶段出错     | 可能是你的，也可能是编译器的 |
| 系统错误 (0x9xxx)        | 外部资源或环境相关       | 环境/配置的                  |

> 错误码前缀就是判断依据。看到 `0x1xxx`~`0x5xxx` 先查自己的代码，
> 看到 `0x6xxx`~`0x7xxx` 基本可以准备提 Issue 了。  
> 如果发现问题复杂到调试指南都解决不了的话，也许可以看看 [如何修复任何BUG](./../../HOW-TO-FIX-ANY-BUG.md) 一文

---

## 第一步：这是你的 bug，还是编译器的 bug？

这是最关键的一步。

### 大概率是你代码的问题

- 错误码以 `0x1`~`0x5` 开头
- 错误信息指向了某个具体的标识符、类型或行号
- 改了对应的代码后，错误消失或变化

### 大概率是编译器的问题

- 错误码以 `0x6`~`0x7` 开头（内部错误）
- 编译器直接崩溃、抛出 Python 异常堆栈（看到 `Traceback (most recent call last)`）
- 你的代码完全符合语法，但编译结果不正确（生成的命令行为异常）
- 修改代码中无关的部分，错误突然消失或变化
- 同一段代码换个优化级别就出问题

### 排查工具箱

按以下顺序逐个尝试，每一步都可能帮你定位或绕过问题：

#### 1. 删除缓存文件

尝试删除所有`.mcdc`和`.mcdci`后缀的文件，若删除后问题不再出现，通常说明错误是由缓存文件引起的。  
一般情况下，这类错误是由于缓存文件写入中途停止等原因导致缓存文件损坏，或是反序列化中存在问题所致，
不必提交，除非出现反复存在，缓存始终无法命中等问题。

#### 2. 逐级降低优化级别

```bash
# 默认 -O 2，先降到 1
python main.py your_code.mcdl -O 1

# 还不行，降到 0（关闭所有优化）
python main.py your_code.mcdl -O 0
```

如果 `-O 0` 下问题消失，说明是某个优化 Pass 引入的 bug。这是编译器的问题， 但你可以在 `-O 0` 或 `-O 1` 下继续工作，同时提
Issue。

#### 3. 开启调试模式

```bash
python main.py your_code.mcdl --debug
```

调试模式会做三件事：

- 在终端输出最终的 IR 指令序列（编译器中间表示），你可以对照检查逻辑是否正确
- 编译器遇到 `CompilationError` 时会抛出完整堆栈而非静默退出
- **日志会写入 `logs/dovetail.log` 文件**，包含解析耗时、AST 遍历耗时、IR 优化耗时、 代码生成耗时等详细信息——即使终端输出看不够，日志文件里都有

#### 4. 输出 IR 临时文件

```bash
python main.py your_code.mcdl --output-temp-file
```

会在输出目录生成一个 `.mcdc` 临时文件，里面是序列化后的 IR 数据（二进制格式）。 如果你在提 Issue，把这个文件附上有助于开发者快速复现。

#### 5. 禁用插件（⚠️ 注意副作用）

```bash
python main.py your_code.mcdl --disable-plugins
```

**重要**：`--disable-plugins` 不仅禁用第三方插件，还会禁用内置插件—— **包括 `je1215` 后端，以及加载插件的插件
`plugin_loader` ~何意味~**。后端是作为插件加载的（位于`dovetail/plugins/je1215/`）， 禁用后编译器会报
"没有找到适合该配置的合适后端"。

所以 `--disable-plugins` 的正确用法是：

- 用来确认问题是否由 **第三方插件**引起
- 如果禁用后报"后端不存在"，说明问题是"没有第三方插件干扰"——这反而是好事， 说明问题出在编译器核心或你的代码本身
- 如果你有多个后端插件，可以改用 `--backend <名称>` 手动指定一个来排查

#### 6. 对照示例

从 `examples/` 目录里找一个最接近你写法的例子：

```bash
# 直接编译示例文件，确认编译器本身工作正常
python main.py examples/example1.mcdl -o target

# 用同样的参数编译你的代码
python main.py your_code.mcdl -o target -O 2 -mcv 1.21.5
```

逐行对比你的代码和示例的差异。

#### 7. 逐步删减

把你的代码删到最小可复现版本——删掉一切无关的函数、变量、include， 只保留能触发问题的最小代码块。如果删着删着问题没了，说明是某段特定写法触发的。

## 第二步：如果是你的代码的问题

### 语法错误 (0x1xxx)

报错信息会告诉你缺了什么符号、哪个写法不合法。逐项排查：

- **括号/大括号不匹配**：数一下 `{` `}` 和 `(` `)` 的数量
- **缺少类型注解**：函数参数必须有类型标注（`fn foo(x: int)` 而非 `fn foo(x)`）
- **include 路径错误**：检查路径字符串是否正确、文件是否真实存在、是否有循环包含
- **无效注解**：`@注解名` 拼写错误或使用了不存在的注解
- **空结构体**：`struct` 定义不能为空
- **默认参数位置**：带默认值的参数必须放在无默认值参数之后

### 语义错误 (0x2xxx~0x5xxx)

代码语法没问题，但逻辑上不通。逐项排查：

- **类型不匹配**：赋值或传参时类型对不上，检查变量声明的类型
- **未定义的符号**：变量名/函数名拼错了，或者作用域不对，或者忘记 `include` 对应文件
- **参数数量不匹配**：调用函数时传的参数个数和定义不一致
- **不可调用**：你试图调用一个不是函数的东西
- **可变性冲突**：尝试修改 `const` 或未声明 `mut` 的变量
- **私有成员访问**：试图访问类的私有成员
- **不可迭代**：对不支持迭代的类型使用了 `for` 循环
- **未实现接口方法**：类声明实现某接口但缺少必需的方法

### 符号解析错误 (0x3xxx)

- **未定义变量/函数**：检查拼写、检查 `include` 顺序、检查作用域嵌套
- **符号类别错误**：把变量当函数调用，或把函数当变量使用

### 控制流错误 (0x4xxx)

- **break/continue 在循环外**：这两个语句只能在循环体内使用
- **返回类型不匹配**：`return` 的值类型和函数声明的返回类型不一致
- **缺少返回语句**：函数声明了返回类型但所有路径都没有 `return`
- **递归超限**：递归深度超过限制，考虑改用迭代或增大限制

### 通用建议

- **看行号**：错误信息里的行号是起点，真正的错误可能在那行或前一行
- **检查最近的改动**：如果你刚改了某段代码，先看那里
- **简化重现**：把问题代码块单独拿出来，用最小用例确认
- **一个错误只改一处**：不要一次改五处然后不知道哪个修复了问题（或者哪个引入了新问题）

## 第三步：如果是编译器的问题

### 你能做的临时绕行

1. **换优化级别**：`-O 0` 关闭所有优化，`-O 1` 减少优化
2. **换后端**：如果你有多个后端可用，用 `--backend <名称>` 指定其他后端
3. **调整写法**：如果某段特定写法触发 bug，尝试换一种等价写法
4. **清除缓存**：删除源文件同目录下的 `.mcdc` 文件（如果存在），排除缓存导致旧代码生效
5. **拆分文件**：如果是大型文件触发的问题，尝试拆分成多个 `include` 文件

### 提交 Bug 报告

去项目仓库提 Issue，附上以下信息：

- **最小复现用例**：删掉一切无关代码，只保留能触发问题的最小 `.mcdl` 文件
- **完整编译命令**：你用的完整命令行参数（包括 `-O`、`-mcv`、`--backend` 等）
- **编译器版本**：运行 `python main.py --version` 获取
- **错误输出**：完整的错误信息或异常堆栈
- **期望行为**：你觉得正确的输出应该是什么
- **调试日志**（如有）：附上 `--debug` 模式下生成的 `logs/dovetail.log`
- **IR 临时文件**（如有）：用 `--output-temp-file` 生成的 `.mcdc` 文件

> 别只贴一句"它报错了"。没有最小复现用例的 bug 报告约等于没有 bug 报告。

## 第四步：环境与配置问题

有时候 bug 既不是你的也不是编译器的——是环境没配对。

### 标准库路径

编译器默认在 `./lib` 目录下查找标准库。如果找不到会直接报错。

```bash
# 方式一：命令行指定
python main.py your_code.mcdl --lib-path /path/to/lib

# 方式二：环境变量指定
export DOVETAIL_LIB_PATH=/path/to/lib
python main.py your_code.mcdl
```

### Minecraft 版本

某些语法特性或后端能力与 Minecraft 版本相关。用 `-mcv` 指定目标版本：

```bash
python main.py your_code.mcdl -mcv 1.21.5
```

如果报 "不支持的目标版本" 或 "没有找到适合该配置的合适后端"， 说明当前可用的后端插件不支持你指定的版本。

### 目录编译配置

如果是编译整个目录，目录下必须有 `pack.config` 文件，格式如下：

```json
{
  "main": "src/main.mcdl",
  "description": "可选的描述字段"
}
```

格式不正确会报配置错误。

## 第五步：环境变量参考

以下是编译器会读取的环境变量，在排查问题时可能用得上：

### `DOVETAIL_LIB_PATH`

指定标准库搜索路径。等同于 `--lib-path` 参数，优先级低于命令行参数。

```bash
export DOVETAIL_LIB_PATH=/path/to/standard/lib
```

### `USED_MIRROR_GITHUB_CN`

设为 `1` 时，编译器下载 GitHub 资源（如自动获取的 Minecraft 库文件）会 **直接使用中国大陆镜像站**， 不走原始 GitHub
地址，也不做回退。适用于国内网络环境。

```bash
export USED_MIRROR_GITHUB_CN=1
```

如果不设置此变量，编译器会先尝试原始 GitHub 地址，失败后依次尝试多个镜像站。

### `PLUGIN_DEBUG`

设为任意非空值时，插件加载失败会输出完整的 Python 异常堆栈（`traceback`）。 用于排查插件加载问题（如后端插件加载失败、第三方插件语法错误等）。

```bash
export PLUGIN_DEBUG=1
python main.py your_code.mcdl
```

如果不设置此变量，插件加载失败只会输出一行简短错误信息，不包含堆栈。

### 代理相关环境变量

编译器下载资源时会自动读取以下环境变量作为代理配置：

| 变量                          | 用途                                 |
|-------------------------------|--------------------------------------|
| `HTTP_PROXY` / `http_proxy`   | HTTP 请求代理                        |
| `HTTPS_PROXY` / `https_proxy` | HTTPS 请求代理                       |
| `ALL_PROXY` / `all_proxy`     | 通用代理（同时作用于 HTTP 和 HTTPS） |

如果你在使用 Clash、v2ray 等代理工具，确保这些变量已正确设置， 否则可能导致依赖文件下载失败。

## 速查表

| 症状                     | 先试什么                                                |
|--------------------------|---------------------------------------------------------|
| 语法解析报错 (0x1xxx)    | 检查括号匹配、类型注解、include 路径                    |
| "未定义的符号" (0x3xxx)  | 检查拼写、作用域、include 顺序                          |
| 类型不匹配 (0x2xxx)      | 检查变量声明的类型、函数签名                            |
| 编译器崩溃 / Python 异常 | 加 `--debug` 看完整堆栈，加 `PLUGIN_DEBUG=1` 看插件堆栈 |
| 生成的命令行为异常       | 逐级降低优化级别（`-O 1` → `-O 0`）排查                 |
| 改了代码但输出没变       | 删除 `.mcdc` 缓存文件                                   |
| 循环包含报错             | 检查 include 链，断开环                                 |
| 标准库找不到             | 用 `--lib-path` 或 `DOVETAIL_LIB_PATH` 指定路径         |
| "没有找到合适后端"       | 检查是否错误设置了`mcv`等参数；用 `--backend` 手动指定  |
| 库文件下载失败           | 设置 `USED_MIRROR_GITHUB_CN=1` 或检查代理环境变量       |
| 插件加载失败             | 设置 `PLUGIN_DEBUG=1` 查看完整堆栈                      |
| 目录编译报配置错误       | 检查 `pack.config` 是否存在且 JSON 格式正确             |
| 需要查看详细日志         | 加 `--debug`，查看 `logs/dovetail.log`                  |

---

> *"It works on my machine!" — 这句话从来不是解决方案。*
> 但如果你开了 `--debug` 还是 works on your machine，那可能真的是环境问题。
