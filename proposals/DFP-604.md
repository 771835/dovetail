## 摘要

本提案规范 Dovetail 项目的推荐目录结构、`dovetail.toml`
配置文件格式，以及构建工具作为独立程序的职责与接口契约。构建工具负责读取项目配置、管理依赖、调度编译、执行钩子、组织输出产物，通过与编译器的命令行接口交互，将高层项目配置映射为编译器可接受的参数。

---

## 动机

### 问题陈述

1. **项目组织无约定**：标准库、用户代码、测试代码无明确边界，大型项目缺少组织指导
2. **编译器与工具链职责混淆**：编译器不应读取配置文件、管理依赖或执行钩子
3. **缺少构建工具规范**：当前仅有简陋的 `pack.config`（JSON 格式），无法支撑依赖管理、增量编译、钩子系统等工具链功能
4. **构建工具定位不明**：构建工具应是独立程序还是编译器插件？需要明确

### 设计目标

- **独立程序**：构建工具是与编译器平行的独立可执行程序，非编译器插件
- **清晰接口**：构建工具与编译器之间通过命令行参数交互，不共享内部状态
- **编译器不感知构建工具**：编译器不读取 `dovetail.toml`，不接受构建工具特有的输入格式
- **可替换**：用户可选择不同的构建工具实现，只要遵守接口契约

## 技术规范

### 1. 构建工具的定位

#### 1.1 构建工具是独立程序

构建工具 `dovetail-build` 是一个独立可执行的程序，与编译器 `dovetail` 平行存在：

```
┌─────────────────┐     命令行调用     ┌─────────────────┐
│  dovetail-build │ ─────────────────→ │    dovetail     │
│  （构建工具）    │                    │   （编译器）     │
└─────────────────┘                    └─────────────────┘
```

**关键约束：**

- 构建工具通过 **子进程调用** 编译器，传递命令行参数
- 编译器通过 **退出码和标准输出/错误流** 返回结果
- 两者不共享内存、不共享配置对象、不共享内部状态
- 构建工具可以被替换为任何遵守接口契约的程序

#### 1.2 构建工具与编译器的职责划分

| 职责                           | 编译器 | 构建工具 |
|--------------------------------|--------|----------|
| 解析 `include` 语句            | 是     | -        |
| 路径搜索与解析                 | 是     | -        |
| 重复包含去重                   | 是     | -        |
| 循环依赖检测                   | 是     | -        |
| 语法/语义分析                  | 是     | -        |
| IR 生成与优化                  | 是     | -        |
| 后端代码生成                   | 是     | -        |
| 读取项目配置文件               | -      | 是       |
| 依赖管理（下载、版本解析）     | -      | 是       |
| 增量编译调度                   | -      | 是       |
| 并行编译调度                   | -      | 是       |
| 钩子执行                       | -      | 是       |
| 输出打包（`pack.mcmeta`、zip） | -      | 是       |

### 2. 编译器命令行接口

构建工具调用编译器时，必须遵守以下接口规范。

#### 2.1 编译器输入

**命令行格式：**

```bash
dovetail <input_file> [options]
```

**必选参数：**

| 参数           | 类型     | 说明                  |
|----------------|----------|-----------------------|
| `<input_file>` | 文件路径 | 入口 `.mcdl` 文件路径 |

**可选参数：**

| 参数             | 短形式 | 类型        | 默认值                 | 说明           |
|------------------|--------|-------------|------------------------|----------------|
| `--lib-path`     | `-l`   | 目录路径    | `lib/`（项目根目录下） | 标准库搜索路径 |
| `-O`             | —      | 整数（0–2） | 来自 `CompileConfig`   | 优化级别       |
| `-o`             | —      | 目录路径    | 当前目录               | 输出目录       |
| `--backend`      | —      | 字符串      | 自动选择               | 后端名称       |
| `--namespace`    | —      | 字符串      | —                      | 数据包命名空间 |
| `--debug`        | —      | 标志        | `False`                | 调试模式       |
| `--experimental` | —      | 标志        | `False`                | 实验性功能     |

- 完整请见编译器实际实现

#### 2.2 编译器输出

**标准输出流（stdout）：**

编译器 **不得** 向 stdout 输出非结构化信息。保留 stdout 用于未来机器可读输出格式。

**标准错误流（stderr）：**

所有诊断信息（错误、警告、信息）输出到 stderr，格式遵循 [DFP-7](./DFP-7.md) 的错误报告规范。

**退出码：**

| 退出码 | 含义                 |
|--------|----------------------|
| `0`    | 编译成功             |
| `1`    | 编译失败（存在错误） |
| `2`    | 命令行参数错误       |

**输出产物：**

编译成功时，在 `-o` 指定的目录下生成 Minecraft 数据包结构：

```
<output_dir>/
├── pack.mcmeta
└── data/
    └── <namespace>/
        └── functions/
            └── *.mcfunction
```

#### 2.3 编译器可用环境变量

| 变量                   | 类型     | 说明           | 优先级                                    |
|------------------------|----------|----------------|-------------------------------------------|
| `DOVETAIL_LIB_PATH`    | 目录路径 | 标准库搜索路径 | 低于 `--lib-path` 命令行参数              |
| `DOVETAIL_DESCRIPTION` | 字符串   | 数据包描述     | 低于 `pack.config` (`pack.config` 已弃用) |

### 3. 项目结构约定

> **注意**：本节为面向编译器工具链的推荐规范，当前编译器不强制执行。

#### 3.1 推荐目录结构

```
my_project/
├── src/                    # 用户源代码
│   ├── main.mcdl           # 主入口文件
│   ├── game/
│   │   ├── player.mcdl
│   │   └── world.mcdl
│   └── utils/
│       └── helpers.mcdl
├── lib/                    # 第三方库（可选）
│   └── external_lib/
│       ├── __init__.mcdl
│       └── module.mcdl
├── tests/                  # 测试文件（可选）
│   ├── test_game.mcdl
│   └── test_utils.mcdl
├── docs/                   # 项目文档（可选）
│   └── README.md
├── hook/                   # 编译钩子（可选）
│   ├── pre_build.sh
│   └── post_build.sh
├── build/                  # 编译输出（工具生成）
│   └── datapack/
├── dovetail.toml           # 项目配置文件（推荐）
└── README.md
```

#### 3.2 目录职责说明

| 目录     | 职责          | 参与编译                 | 管理方        |
|----------|---------------|--------------------------|---------------|
| `src/`   | 项目源代码    | 是                       | 用户          |
| `lib/`   | 第三方库/依赖 | 是（通过 `--lib-path`）  | 构建工具/用户 |
| `tests/` | 测试代码      | 是，但不并入最终编译产物 | 构建工具      |
| `build/` | 编译产物      | 否（输出）               | 构建工具      |
| `docs/`  | 项目文档      | 否                       | 用户          |
| `hook/`  | 编译钩子脚本  | 否（在编译前后执行）     | 构建工具      |

#### 3.3 特殊文件约定

**主入口文件：**

- 默认为 `src/main.mcdl`
- 可通过构建工具配置或直接传递给编译器 `<input_file>` 指定

**模块索引文件（未来）：**

- 目录下的 `__init__.mcdl` 作为默认导出
- 支持 `include "collections"` 而非 `include "collections/stack.mcdl"`

### 4. 项目配置文件：`dovetail.toml`

#### 4.1 现有实现与推荐规范

当前编译器使用 `pack.config`（JSON 格式）：

```json
{
  "main": "src/main.mcdl",
  "description": "A Minecraft datapack"
}
```

> `pack.config` 为现有简陋实现， **不作为本提案的规范目标**。未来应迁移至 `dovetail.toml`。

#### 4.2 `dovetail.toml` 规范

构建工具读取并解析 `dovetail.toml`，将其映射为编译器命令行参数。

**完整格式：**

```toml
[package]
name = "my_project"                           # 必需，项目名称
version = "1.0.0"                             # 必需，语义化版本号
authors = ["Your Name <your.email@example.com>"]  # 可选
description = "A Minecraft datapack"           # 可选
license = "MIT"                               # 可选

[build]
entry = "src/main.mcdl"                       # 必需，入口文件路径（相对于项目根目录）
output = "build"                              # 可选，输出目录，默认 "build"
tool = "default"                              # 可选，构建工具名称，默认 "default"

[paths]
sources = ["src"]                             # 可选，源码目录列表，默认 ["src"]
libraries = ["lib"]                           # 可选，库目录列表，默认 ["lib"]
includes = []                                 # 可选，额外搜索路径列表，默认空

[compiler]
lib_path = ""                                 # 可选，标准库路径（空则使用编译器默认值）
optimization = 2                              # 可选，优化级别 0-2，默认 2
backend = ""                                  # 可选，后端名称（空则自动选择）
namespace = ""                                # 可选，命名空间（空则使用 package.name）
debug = false                                 # 可选，调试模式，默认 false
experimental = false                          # 可选，实验性功能，默认 false

[hooks]
pre_build = ""                                # 可选，编译前钩子脚本路径
post_build = ""                               # 可选，编译后钩子脚本路径

[dependencies]
# 未来扩展，当前为空
# example_lib = { path = "../example_lib" }
# remote_lib = { git = "https://github.com/user/lib.git", tag = "v1.0.0" }
```

#### 4.3 配置字段与编译器参数的映射

| `dovetail.toml` 字段      | 映射到的编译器参数  | 转换规则                                 |
|---------------------------|---------------------|------------------------------------------|
| `[build].entry`           | `<input_file>`      | 直接传递，相对于项目根目录解析           |
| `[build].output`          | `-o`                | 直接传递，相对于项目根目录解析           |
| `[compiler].lib_path`     | `--lib-path` / `-l` | 非空时传递；空则不传（使用编译器默认值） |
| `[compiler].optimization` | `-O`                | 直接传递                                 |
| `[compiler].backend`      | `--backend`         | 非空时传递；空则不传                     |
| `[compiler].namespace`    | `--namespace`       | 非空时传递；空则使用 `[package].name`    |
| `[compiler].debug`        | `--debug`           | 为 `true` 时传递                         |
| `[compiler].experimental` | `--experimental`    | 为 `true` 时传递                         |

#### 4.4 配置文件验证规范

**构建工具在读取 `dovetail.toml` 后必须验证：**

| 验证项                    | 条件                       | 失败行为       |
|---------------------------|----------------------------|----------------|
| `[package].name`          | 非空字符串                 | 报错终止       |
| `[package].version`       | 符合语义化版本格式         | 报错终止       |
| `[build].entry`           | 非空字符串且对应文件存在   | 报错终止       |
| `[compiler].optimization` | 整数，0 ≤ x ≤ 3            | 报错终止       |
| `[hooks].pre_build`       | 为空或对应文件存在且可执行 | 警告（非终止） |
| `[hooks].post_build`      | 为空或对应文件存在且可执行 | 警告（非终止） |

### 5. 构建工具的执行流程

#### 5.1 标准构建流程

```
读取配置 → 验证配置 → pre_build → 编译器 → post_build → 打包输出
```

#### 5.2 各步骤的输入输出规范

**步骤 1：读取配置**

| 项目     | 说明                                     |
|----------|------------------------------------------|
| 输入     | 项目根目录下的 `dovetail.toml` 文件      |
| 输出     | 结构化的配置对象                         |
| 失败条件 | 文件不存在、格式错误、字段验证失败       |
| 失败行为 | 向 stderr 输出错误信息，以非零退出码终止 |

**步骤 2：执行 `pre_build` 钩子**

| 项目     | 说明                                                   |
|----------|--------------------------------------------------------|
| 输入     | `[hooks].pre_build` 指定的脚本路径 + 环境变量（见 §6） |
| 输出     | 无（钩子可能修改文件系统，如生成代码）                 |
| 失败条件 | 脚本以非零退出码退出                                   |
| 失败行为 | 构建工具向 stderr 报告钩子失败，以非零退出码终止构建   |

**步骤 3：调用编译器**

| 项目     | 说明                                               |
|----------|----------------------------------------------------|
| 输入     | 由 §4.3 映射规则生成的编译器命令行参数             |
| 输出     | 编译产物（在 `[build].output` 目录下）             |
| 失败条件 | 编译器以非零退出码退出                             |
| 失败行为 | 构建工具转发编译器的 stderr 输出，以相同退出码终止 |

**步骤 4：执行 `post_build` 钩子**

| 项目     | 说明                                                    |
|----------|---------------------------------------------------------|
| 输入     | `[hooks].post_build` 指定的脚本路径 + 环境变量（见 §6） |
| 输出     | 无（钩子可能部署产物，如复制到 Minecraft 目录）         |
| 失败条件 | 脚本以非零退出码退出                                    |
| 失败行为 | 构建工具向 stderr 报告钩子失败，以非零退出码终止        |

**步骤 5：打包输出**

| 项目     | 说明                                                                   |
|----------|------------------------------------------------------------------------|
| 输入     | 编译产物目录                                                           |
| 输出     | 完整的 Minecraft 数据包目录结构（含 `pack.mcmeta`），可选压缩为 `.zip` |
| 失败条件 | 输出目录不存在或权限不足                                               |
| 失败行为 | 向 stderr 报告错误，以非零退出码终止                                   |

#### 5.3 构建工具的退出码

| 退出码 | 含义                             |
|--------|----------------------------------|
| `0`    | 构建成功                         |
| `1`    | 构建失败（编译错误）             |
| `2`    | 配置错误（`dovetail.toml` 无效） |
| `3`    | 钩子失败                         |
| `4`    | 打包失败                         |

#### 5.4 `script` 子命令

`dovetail-build script <脚本路径>`

该子命令主要供构建工具内部调用，用于执行钩子程序， **可选**实现。

### 6. 钩子系统

#### 6.1 钩子触发时机

当前规范仅定义两个钩子时机：

| 钩子         | 触发时机       | 用途示例                              |
|--------------|----------------|---------------------------------------|
| `pre_build`  | 编译器调用之前 | 生成版本文件、清理旧产物、代码生成    |
| `post_build` | 编译器调用之后 | 部署到 Minecraft 目录、运行测试、通知 |

#### 6.2 钩子的输入：环境变量

构建工具在执行钩子脚本前，必须设置以下环境变量：

| 环境变量                | 类型          | 说明                   | 来源                                       |
|-------------------------|---------------|------------------------|--------------------------------------------|
| `DOVETAIL_PROJECT_ROOT` | 目录路径      | 项目根目录的绝对路径   | 构建工具推断                               |
| `DOVETAIL_PROJECT_NAME` | 字符串        | 项目配置的名称         | `[package].name`	                           |
| `DOVETAIL_BUILD_DIR`    | 目录路径      | 构建输出目录的绝对路径 | `[build].output`                           |
| `DOVETAIL_ENTRY_FILE`   | 文件路径      | 入口文件的绝对路径     | `[build].entry`                            |
| `DOVETAIL_BACKEND`      | 字符串        | 后端名称               | `[compiler].backend`                       |
| `DOVETAIL_OPTIMIZATION` | 整数字符串    | 优化级别               | `[compiler].optimization`                  |
| `DOVETAIL_NAMESPACE`    | 字符串        | 数据包命名空间         | `[compiler].namespace` 或 `[package].name` |
| `DOVETAIL_LIB_PATH`     | 目录路径      | 标准库路径             | `[compiler].lib_path`                      |
| `DOVETAIL_VERSION`      | 字符串        | 项目版本号             | `[package].version`                        |
| `DOVETAIL_DEBUG`        | 布尔值(`1/0`) | 调试标识               | `[compiler].debug`                         |
| `DOVETAIL_HOOK_STAGE`   | 字符串        | 钩子脚本所在的阶段     | 构建工具推断                               |

**约定：**

- 所有路径环境变量必须为 **绝对路径**
- 空值的字段设置为空字符串（不删除变量）
- 钩子脚本不应修改这些环境变量

#### 6.3 钩子的输出

| 项目           | 说明                         |
|----------------|------------------------------|
| 标准输出       | 构建工具**可选**捕获并显示   |
| 标准错误       | 构建工具**可选**捕获并显示   |
| 退出码         | `0` 表示成功，非零表示失败   |
| 文件系统副作用 | 允许（如生成代码、部署产物） |

#### 6.4 钩子脚本的格式要求

- 脚本文件必须具有 **可执行权限**（Unix 系统）
- 支持的脚本类型：Shell 脚本（`.sh`）、Python 脚本（`.py`）
- Shell 脚本推荐以 `#!/bin/bash` 或类似 shebang 开头
- 构建工具通过 `dovetail-build script <脚本路径>` 子命令执行脚本。该子命令负责注入环境变量并运行脚本，在打包环境下无需外部
  Python 解释器。

**示例：**

```bash
# hook/pre_build.sh
#!/bin/bash
set -e

echo "Generating version file for $DOVETAIL_VERSION..."
VERSION=$(git describe --tags --always 2>/dev/null || echo "$DOVETAIL_VERSION")
echo "let VERSION = \"$VERSION\"" > "$DOVETAIL_PROJECT_ROOT/src/version.mcdl"

# 清理旧构建
rm -rf "$DOVETAIL_BUILD_DIR"/*
```

```bash
# hook/post_build.sh
#!/bin/bash
set -e

echo "Build completed: $DOVETAIL_BUILD_DIR"

# 可选：复制到 Minecraft 世界目录
MINECRAFT_WORLD="$HOME/.minecraft/saves/MyWorld/datapacks"
if [ -d "$MINECRAFT_WORLD" ]; then
   cp -r "$DOVETAIL_BUILD_DIR" "$MINECRAFT_WORLD/my_datapack"
   echo "Deployed to: $MINECRAFT_WORLD/my_datapack"
fi
```

### 7. 依赖管理（未来）

> 以下功能为未来扩展方向，不在当前构建工具实现范围内。

#### 7.1 依赖声明格式

```toml
[dependencies]
# 本地路径依赖
example_lib = { path = "../example_lib" }

# Git 远程依赖
remote_lib = { git = "https://github.com/user/lib.git", tag = "v1.0.0" }

# 指定分支
dev_lib = { git = "https://github.com/user/lib.git", branch = "develop" }
```

#### 7.2 依赖解析的输入输出

| 项目   | 说明                          |
|--------|-------------------------------|
| 输入   | `[dependencies]` 段的依赖声明 |
| 输出   | `lib/` 目录下的依赖文件       |
| 副作用 | 生成 `dovetail.lock` 锁定文件 |

#### 7.3 依赖锁定文件

构建工具应在首次依赖解析后生成 `dovetail.lock`，记录每个依赖的精确版本/提交哈希，确保可复现构建。

### 9. 扩展钩子时机（未来）

> 以下功能为未来扩展方向，不在当前构建工具实现范围内。

#### 9.1 文件级钩子时机

| 钩子            | 触发时机         | 说明             |
|-----------------|------------------|------------------|
| `pre_compile`   | 单个文件编译前   | 可用于代码预处理 |
| `post_compile`  | 单个文件编译后   | 可用于代码后处理 |
| `pre_optimize`  | 优化阶段开始前   | 可用于 IR 检查   |
| `post_optimize` | 优化阶段结束后   | 可用于 IR 审计   |
| `pre_package`   | 数据包打包开始前 | 可用于产物修改   |

文件级钩子在 `dovetail.toml` 的 `[hooks]` 段中声明：

```toml
[hooks]
pre_build = "hook/pre_build.py"
post_build = "hook/post_build.py"
pre_compile = "hook/pre_compile.py"   # 可选，每个文件编译前触发
post_compile = "hook/post_compile.py"  # 可选，每个文件编译后触发
```

未设置文件级钩子时，相关机制完全不激活，对普通构建零开销。

#### 9.2 文件级钩子的额外环境变量

文件级钩子在 §6.2 的基础上，额外注入以下环境变量：

| 环境变量                | 类型     | 说明                       | 适用钩子                      |
|-------------------------|----------|----------------------------|-------------------------------|
| `DOVETAIL_CURRENT_FILE` | 文件路径 | 当前正在编译的文件绝对路径 | `pre_compile`、`post_compile` |

#### 9.3 跨进程事件机制

编译器核心与构建工具进程隔离，文件级钩子的触发依赖跨进程通信。 设计方案如下：

**总体架构：**

```
编译器进程                          构建工具进程
──────────────────────────────      ──────────────────────────────
FileCompileEvent.call_event()
  └→ HookBridgePlugin（内置插件）
       └→ 写入命名管道 ──────────→  读管道线程
                                      └→ dovetail-build script
                                           └→ 钩子脚本
```

**命名管道：**

- 构建工具在启动编译器前创建命名管道，将管道名通过环境变量
  `DOVETAIL_HOOK_PIPE` 传入编译器子进程
- Windows：`\\.\pipe\dovetail_hook_<pid>`
- Unix：`/tmp/dovetail_hook_<pid>`（mkfifo）

**事件消息格式（JSON Lines）：**

每条消息为一行 JSON，以 `\n` 结尾：

```json
{
  "event": "file_compiled",
  "file": "/abs/path/to/player.mcdl"
}
{
  "event": "done"
}
```

| 字段    | 类型   | 说明                                    |
|---------|--------|-----------------------------------------|
| `event` | 字符串 | 事件类型：`file_compiled` \| `done`     |
| `file`  | 字符串 | 文件绝对路径（仅 `file_compiled` 携带） |

**HookBridgePlugin：**

- 内置于编译器插件目录，默认不激活
- 检测到 `DOVETAIL_HOOK_PIPE` 环境变量时自动激活，连接管道
- 注册 `FileCompileEvent` 处理器，每次事件触发时向管道写入一行 JSON
- 编译结束时写入 `{"event": "done"}` 并关闭管道
- 未检测到环境变量时完全静默，不影响普通编译流程

**构建工具行为：**

- 仅当 `[hooks]` 中存在 `pre_compile` 或 `post_compile` 时才创建管道
- 启动独立线程读取管道，主线程等待编译器子进程退出
- 收到 `file_compiled` 事件后，调用 `dovetail-build script` 触发对应钩子
- 读管道线程在收到 `done` 或管道关闭后退出，join 超时上限 5 秒
