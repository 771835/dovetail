## 摘要

本提案规范 Dovetail 的文件包含机制（`include`
语句）的语法、语义和路径解析规则，以及面向编译器工具链的项目目录结构与配置文件推荐约定。构建工具、依赖管理等编译工具链职责由独立的构建系统插件承担，不在本提案范围内。

---

## 动机

### 问题陈述

1. **`include` 语义不明**
   - 路径解析规则不明确
   - 重复包含行为未规范
   - 循环依赖检测缺失

2. **项目组织无约定**
   - 标准库、用户代码、测试代码无明确边界
   - 大型项目缺少组织指导

3. **编译器职责模糊**
   - 编译器应负责哪些路径搜索？
   - 哪些职责应交由外部工具？

### 设计目标

- **最小核心**：编译器仅负责 `include` 语句的基本语义
- **清晰边界**：区分编译器职责与构建工具职责
- **简洁语法**：沿用 C 风格的包含机制，符合 Dovetail 的 Python/C 混合风格
- **可扩展性**：为构建工具插件预留扩展点

## 技术规范

### 1. `include` 语句

#### 1.1 语法定义

```lark
include: "include" literal
```

**示例：**

```mcdl
include "mathlib.mcdl"
include "utils/helpers.mcdl"
include "./local_module.mcdl"
include "../shared/config.mcdl"
```

**约束：**

- `include` 为保留关键字
- `literal` 在语义层面仅接受字符串字面量，编译器应对非字符串字面量报错
- 路径分隔符统一使用正斜杠 `/`（编译器负责平台转换）
- 路径字符串 **必须包含** `.mcdl` 扩展名，编译器不自动追加

#### 1.2 语义

**`include` 的作用：**

1. 将指定文件的 AST 合并到当前文件的解析过程中（类似 C 的 `#include`）
2. 在合并前，编译器处理重复包含和循环依赖
3. 被包含文件中的所有符号（函数、常量等）对包含者可见

**执行时机：**

- 编译器在解析阶段处理 `include` 语句
- 被包含文件先于当前文件完成语义分析
- 符号表在包含完成后对当前作用域可见

**等价性示例：**

```mcdl
// main.mcdl
include "utils.mcdl"
fn main() {
    helper()
}

// utils.mcdl
fn helper() { ... }

// 语义等价于（概念上）：
// main2.mcdl
fn helper() { ... }  // 来自 utils.mcdl
fn main() {
    helper()
}
```

#### 1.3 重复包含处理

**编译器行为规范：**

编译器 **必须**维护已包含文件的规范路径集合，自动去重：

```mcdl
// a.mcdl
include "common.mcdl"
include "b.mcdl"

// b.mcdl
include "common.mcdl"  // ✅ 合法：编译器自动忽略（已被 a.mcdl 包含）
```

**实现要求：**

- 使用文件系统的 **规范绝对路径**（`resolve()`）作为去重依据
- 解析符号链接的真实路径

**实现参考：**

```python
# IncludeManager 维护已包含路径集合
def add_include_path(self, include_path: Path) -> None:
   resolved_path = str(include_path.resolve())
   if resolved_path not in self._included_paths:
      self._included_paths.add(resolved_path)
      self._include_history.append(resolved_path)


def has_path(self, include_path: Path) -> bool:
   return str(include_path.resolve()) in self._included_paths
```

#### 1.4 循环依赖检测

编译器 **必须**检测并拒绝编译循环依赖：

```mcdl
// a.mcdl
include "b.mcdl"  // a → b

// b.mcdl
include "c.mcdl"  // b → c

// c.mcdl
include "a.mcdl"  // c → a  ❌ 循环：a → b → c → a
```

**实现要求：**

- 使用栈追踪当前包含链
- 检测到已在栈中的文件时报错
- 提供完整依赖路径供调试
- 栈帧应包含文件名（可选是否包含行号等信息）

**实现参考：**

```python
# IncludeManager 使用上下文管理器维护包含栈
@contextmanager
def including(self, include_path: Path, meta: Optional[Meta] = None):
   resolved_path = str(include_path.resolve())

   # 检测循环依赖
   if resolved_path in self._include_stack:
      self._report_circular_dependency(resolved_path, meta)
      raise CircularIncludeException(f"Circular dependency detected: {resolved_path}")

   self._include_stack.append(resolved_path)
   try:
      yield self
   finally:
      if self._include_stack and self._include_stack[-1] == resolved_path:
         self._include_stack.pop()
```

### 2. 路径解析规则

#### 2.1 当前实现

编译器按以下逻辑解析 `include` 路径：

```python
def _search_include_path(self, filepath: Path, meta: Meta) -> Path | None:
   """搜索导入文件的实际路径"""
   if filepath.is_absolute():
      return filepath

   search_paths: list[Path] = [self.config.lib_path, Path.cwd()]
   include_path = next(
      (d / filepath for d in search_paths if (Path(d) / filepath).exists()),
      None
   )

   if include_path:
      return include_path
   else:
      self.error_reporter.report(
         Errors.IncludePathError,
         str(filepath),
         meta=meta
      )
      return None
```

**搜索顺序：**

| 优先级 | 搜索路径     | 说明                                                  |
|--------|--------------|-------------------------------------------------------|
| 1      | 绝对路径     | 若路径本身为绝对路径，直接返回                        |
| 2      | `lib_path`   | 通过 `--lib-path` 或环境变量 `DOVETAIL_LIB_PATH` 指定 |
| 3      | 当前工作目录 | `Path.cwd()`                                          |

**命令行参数：**

```bash
dovetail main.mcdl --lib-path /usr/local/lib/dovetail
```

若未指定 `--lib-path`，默认为项目根目录下的 `lib/` 目录。

**环境变量支持：**

```bash
export DOVETAIL_LIB_PATH=/opt/dovetail/lib
```

#### 2.2 路径类型

当前实现支持以下路径类型：

| 类型         | 语法             | 示例                   | 解析基准                   |
|--------------|------------------|------------------------|----------------------------|
| **绝对路径** | 系统绝对路径     | `"/opt/lib/math.mcdl"` | 直接使用                   |
| **搜索路径** | 无前缀的相对路径 | `"math.mcdl"`          | 依次搜索 `lib_path`、`cwd` |

#### 2.3 文件扩展名处理

**规范：**

- 用户在 `include` 语句中 **必须**编写 `.mcdl` 扩展名
- 编译器不自动追加扩展名

**示例：**

```mcdl
include "math.mcdl"         // ✅ 显式扩展名
include "utils/io.mcdl"     // ✅ 显式扩展名
include "math"              // ❌ 缺少扩展名，文件将无法找到
```

### 3. 项目结构约定

> **注意**：本节为面向编译器工具链的推荐规范，当前编译器不强制执行。

#### 3.1 推荐目录结构

```
my_project/
├── src/                    # 用户源代码
│   ├── main.mcdl           # 主入口文件
│   ├── game/
│   │   ├── player.mcdl
│   │   └── world.mcdl
│   └── utils/
│       └── helpers.mcdl
├── lib/                    # 第三方库（可选）
│   └── external_lib/
│       ├── __init__.mcdl
│       └── module.mcdl
├── tests/                  # 测试文件（可选）
│   ├── test_game.mcdl
│   └── test_utils.mcdl
├── docs/                   # 项目文档（可选）
│   └── README.md
├── hook/                   # 编译钩子（可选）
│   ├── pre_build.sh
│   └── post_build.sh
├── build/                  # 编译输出（工具生成）
│   └── datapack/
├── dovetail.toml           # 项目配置文件（推荐）
└── README.md
```

#### 3.2 目录职责说明

| 目录     | 职责          | 约定                           |
|----------|---------------|--------------------------------|
| `src/`   | 项目源代码    | 推荐搜索路径之一（未来）       |
| `lib/`   | 第三方库/依赖 | 可通过 `--lib-path` 指定       |
| `tests/` | 测试代码      | 由构建工具管理，不参与生产编译 |
| `build/` | 编译产物      | 由构建工具管理                 |
| `docs/`  | 项目文档      | 不参与编译                     |
| `hook/`  | 编译钩子      | 由构建工具在特定时机执行       |

#### 3.3 项目配置文件

##### 3.3.1 当前实现

当前编译器使用 `pack.config`（JSON 格式）作为项目配置文件，包含数据包元信息和入口文件声明：

```json
{
   "main": "src/main.mcdl",
   "description": "A Minecraft datapack"
}
```

> `pack.config` 为现有简陋实现，不作为本提案的规范目标。

##### 3.3.2 推荐规范：`dovetail.toml`

本提案推荐使用 `dovetail.toml` 作为项目配置标准格式，由构建工具解析并传递参数给编译器：

```toml
# dovetail.toml（由构建工具解析，非编译器）
[package]
name = "my_project"
version = "1.0.0"
authors = ["Your Name <your.email@example.com>"]
description = "A Minecraft datapack written in Dovetail"
license = "MIT"

[build]
tool = "default"               # 使用的构建工具名称
entry = "src/main.mcdl"        # 入口文件
output = "target"              # 输出目录

[paths]
sources = ["src"]              # 源码目录
libraries = ["lib"]            # 库目录
includes = ["../shared"]       # 额外搜索路径（传递给 -I，未来）
docs = ["docs"]                # 文档目录
hooks = ["hook"]               # 钨子目录

[compiler]
lib_path = "/usr/local/lib/dovetail"  # 标准库路径（传递给 --lib-path，空则由编译器指定）
optimization = 2                      # 优化级别（传递给 -O）
backend = ""                          # 后端名称（空则自动选择）

[hooks]
# 钩子配置（可选）
pre_build = "hook/pre_build.sh"
post_build = "hook/post_build.sh"

[dependencies]
# 未来扩展：依赖管理
# example_lib = { path = "../example_lib" }
# remote_lib = { git = "https://github.com/user/lib.git", tag = "v1.0.0" }
```

##### 3.3.3 配置字段说明

| 字段           | 位置         | 说明         | 对应编译器参数 |
|----------------|--------------|--------------|----------------|
| `entry`        | `[build]`    | 入口文件路径 | `<input>`      |
| `output`       | `[build]`    | 输出目录     | `-o`           |
| `lib_path`     | `[compiler]` | 标准库路径   | `--lib-path`   |
| `optimization` | `[compiler]` | 优化级别     | `-O`           |
| `backend`      | `[compiler]` | 后端名称     | `--backend`    |
| `includes`     | `[paths]`    | 额外搜索路径 | `-I`（未来）   |

##### 3.3.4 编译器与构建工具的接口

编译器 **不**直接读取 `dovetail.toml`。构建工具读取配置后，将相应参数传递给编译器命令行：

```bash
# 构建工具读取 dovetail.toml 后调用编译器
dovetail src/main.mcdl \
    --lib-path /usr/local/lib/dovetail \
    -O 2 \
    -o target
```

#### 3.4 特殊文件约定

**主入口文件：**

- 默认为 `src/main.mcdl`
- 可通过命令行参数 `<input>` 指定
- 或由构建工具从 `dovetail.toml` 的 `[build].entry` 读取

**模块索引文件（未来）：**

- 目录下的 `__init__.mcdl` 作为默认导出
- 支持 `include "collections"` 而非 `include "collections/stack.mcdl"`

**编译钩子（未来）：**

- `hook/pre_build.sh` 或 `hook/pre_build.py`：编译前执行
- `hook/post_build.sh` 或 `hook/post_build.py`：编译后执行
- 由构建工具负责调用，编译器不处理
- 钩子脚本应具有可执行权限（Unix 系统）

### 4. 编译器职责边界

#### 4.1 编译器必须实现的功能

1. **`include` 语法解析**
   - 识别 `include` 语句
   - 提取路径字符串
   - 验证路径为字符串字面量

2. **路径解析**
   - 按本提案第 2 节规定的算法解析路径
   - 绝对路径直接使用，相对路径搜索 `lib_path` 和 `cwd`

3. **重复包含去重**
   - 维护已包含文件集合
   - 自动忽略重复包含

4. **循环依赖检测**
   - 维护包含栈
   - 检测并报告循环依赖
   - 提供完整依赖链

5. **错误报告**
   - 文件未找到错误
   - 循环依赖错误（含依赖链）
   - 提供清晰的错误位置（文件名、行号）

6. **命令行参数处理**
   - `--lib-path` / `-l`：指定标准库路径
   - 环境变量 `DOVETAIL_LIB_PATH`：备选标准库路径

#### 4.2 编译器不负责的功能

以下职责应由 **外部构建工具**承担：

1. **项目配置管理**
   - 读取 `dovetail.toml` 配置文件
   - 解析构建参数
   - 管理项目元数据
   - 将配置映射为编译器命令行参数

2. **依赖管理**
   - 下载远程依赖（Git、HTTP）
   - 版本解析和冲突检测
   - 依赖锁定文件（lock file）

3. **增量编译**
   - 检测文件修改时间戳
   - 维护编译缓存
   - 仅重编译变更文件及其依赖

4. **并行编译**
   - 多文件并行处理
   - 任务调度和资源管理

5. **输出打包**
   - 生成 `pack.mcmeta`
   - 组织数据包目录结构
   - 压缩为 `.zip` 分发格式

6. **钩子执行**
   - 调用编译前后钩子脚本
   - 传递环境变量
   - 处理钩子执行失败

### 5. 未来计划

> 以下功能为编译器工具链的推荐扩展方向，不在当前编译器实现范围内。

#### 5.1 扩展搜索路径

- 支持 `-I <dir>` 命令行参数添加额外搜索路径
- 支持 `--project-root <dir>` 指定项目根目录
- 搜索优先级：`lib_path` → `cwd` → `src/` → `-I` 指定路径

**示例：**

```bash
dovetail main.mcdl \
    --lib-path /usr/local/lib/dovetail \
    --project-root /home/user/my_project \
    -I lib \
    -I ../shared
```

#### 5.2 相对路径与项目根路径

- 支持 `./` 和 `../` 开头的路径，相对于当前文件所在目录解析
- 支持 `/` 开头的路径，相对于项目根目录解析

**示例：**

```mcdl
include "./local_module.mcdl"     // 相对当前文件
include "../shared/config.mcdl"   // 相对父目录
include "/lib/math.mcdl"          // 相对项目根目录
```

#### 5.3 目录包含

若路径指向目录，编译器可选支持以下行为：

```mcdl
include "collections"
// 搜索顺序：
// 1. collections.mcdl（文件）
// 2. collections/__init__.mcdl（目录索引）
// 3. collections/index.mcdl（目录索引）
```

优先级规则：文件 > 目录索引。

#### 5.4 虚拟模块映射

对于标准库中的核心模块，编译器可选实现内置符号注入：

`include "math.mcdl"` 可能不对应实际的 `math.mcdl` 文件，而是编译器内部实现的虚拟模块。

#### 5.5 钩子系统

构建工具应支持以下钩子触发时机：

```
1. pre_build       - 整个构建开始前
2. pre_compile     - 单个文件编译前
3. post_compile    - 单个文件编译后
4. pre_optimize    - 优化阶段开始前
5. post_optimize   - 优化阶段结束后
6. pre_package     - 数据包打包开始前
7. post_build      - 整个构建结束后
```

构建工具应向钩子脚本传递以下环境变量：

```bash
DOVETAIL_PROJECT_ROOT   # 项目根目录
DOVETAIL_BUILD_DIR      # 构建输出目录
DOVETAIL_ENTRY_FILE     # 入口文件路径
DOVETAIL_BACKEND        # 后端名称
DOVETAIL_OPTIMIZATION   # 优化级别
```

**钩子文件格式示例：**

```bash
# hook/pre_build.sh
#!/bin/bash
set -e

echo "Starting build for project: $DOVETAIL_PROJECT_ROOT"
echo "Generating version file..."

# 生成版本文件
VERSION=$(git describe --tags --always)
echo "let VERSION = \"$VERSION\"" > src/version.mcdl

# 清理旧构建
rm -rf "$DOVETAIL_BUILD_DIR"/*
```

```python
# hook/post_build.py
# !/usr/bin/env python3
import os
import shutil
from pathlib import Path

project_root = Path(os.environ['DOVETAIL_PROJECT_ROOT'])
build_dir = Path(os.environ['DOVETAIL_BUILD_DIR'])

print(f"Build completed: {build_dir}")

# 复制到 Minecraft 世界目录
minecraft_world = Path.home() / '.minecraft/saves/MyWorld/datapacks'
if minecraft_world.exists():
   shutil.copytree(build_dir, minecraft_world / 'my_datapack', dirs_exist_ok=True)
   print(f"Datapack installed to: {minecraft_world}")
```

 1 | include "a.mcdl"
   |         ^^^^^^^^ creates circular dependency
   |
   = note: include chain:
