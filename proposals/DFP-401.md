## 摘要

本提案规范 Dovetail 编译器中 `include`
语句的语法、语义、路径解析规则、重复包含去重及循环依赖检测机制。本提案仅涉及编译器核心职责范围。

---

## 动机

### 问题陈述

1. **`include` 语义不明**：路径解析规则不明确，重复包含行为未规范，循环依赖检测缺失
2. **编译器职责模糊**：编译器应负责哪些路径搜索？`include` 的精确语义边界不清

### 设计目标

- **最小核心**：编译器仅负责 `include` 语句的基本语义——解析、去重、循环检测
- **清晰边界**：编译器不读取项目配置文件，不管理依赖，不执行钩子
- **简洁语法**：沿用 C 风格的包含机制，符合 Dovetail 的 Python/C 混合风格

## 技术规范

### 1. `include` 语句

#### 1.1 语法定义

```lark
include: "include" STRING
```

**约束：**

- `include` 为保留关键字
- `literal` 在语义层面仅接受字符串字面量，非字符串字面量转换成字符串后查找
- 路径分隔符统一使用正斜杠 `/`（编译器负责平台转换）
- 路径字符串 **必须显式包含** `.mcdl` 扩展名，编译器不自动追加

**合法示例：**

```mcdl
include "mathlib.mcdl"
include "utils/helpers.mcdl"
```

#### 1.2 语义

`include` 的作用是将指定文件的 AST 合并到当前文件的解析过程中（类似 C 的 `#include`）。

**执行时机：**

- 编译器在 **解析阶段** 处理 `include` 语句
- 被包含文件先于当前文件完成语义分析
- 符号表在包含完成后对当前作用域可见

**等价性示例：**

```mcdl
// main.mcdl
include "utils.mcdl"
fn main() {
    helper()
}

// utils.mcdl
fn helper() { ... }

// 语义等价于（概念上）：
// main2.mcdl
fn helper() { ... }  // 来自 utils.mcdl
fn main() {
    helper()
}
```

#### 1.3 重复包含处理

编译器 **必须** 维护已包含文件的规范路径集合，自动去重：

```mcdl
// a.mcdl
include "common.mcdl"
include "b.mcdl"

// b.mcdl
include "common.mcdl"  // ✅ 合法：编译器自动忽略（已被 a.mcdl 包含）
```

**去重依据：** 使用文件系统的 **规范绝对路径**（`Path.resolve()`），解析符号链接的真实路径。

**编译器接口规范：**

| 操作                 | 输入   | 输出                          | 副作用                                           |
|----------------------|--------|-------------------------------|--------------------------------------------------|
| `add_include_path`   | `Path` | 无                            | 若路径未收录，将其规范绝对路径加入集合与历史列表 |
| `has_path`           | `Path` | `bool`                        | 无                                               |
| `get_included_paths` | 无     | `list[str]`（按首次包含顺序） | 无                                               |

#### 1.4 循环依赖检测

编译器 **必须** 检测并拒绝循环依赖：

```mcdl
// a.mcdl
include "b.mcdl"  // a → b

// b.mcdl
include "c.mcdl"  // b → c

// c.mcdl
include "a.mcdl"  // c → a  ❌ 循环：a → b → c → a
```

**检测机制：** 使用栈追踪当前包含链。检测到目标路径已在栈中时，报告 `Errors.CircularInclude` 错误并抛出
`CircularIncludeException`。

**编译器接口规范：**

| 操作                        | 输入                     | 输出                      | 副作用                                         |
|-----------------------------|--------------------------|---------------------------|------------------------------------------------|
| `including`（上下文管理器） | `Path`, `Optional[Meta]` | `IncludeManager`（yield） | 路径压栈；退出时弹栈；检测到循环时报错并抛异常 |
| `get_include_stack`         | 无                       | `list[str]`（当前栈快照） | 无                                             |
| `get_entry_file`            | 无                       | `Optional[Path]`          | 无                                             |

**初始化行为：** 若构造时传入 `entry_file`，该文件的规范绝对路径自动压入栈底，作为包含链起点。

### 2. 路径解析规则

#### 2.1 解析算法

编译器按以下逻辑解析 `include` 路径：

**输入：** `include` 语句中的路径字符串 `filepath`，代码元信息 `meta`

**输出：** 解析后的绝对路径，或 `None`（未找到时报告 `Errors.IncludePathError`）

**算法：**

1. 若 `filepath` 为绝对路径 → 直接返回
2. 否则，按以下搜索顺序依次查找：
    - `lib_path`（来自 `CompileConfig.lib_path`）
    - `Path.cwd()`（当前工作目录）
3. 找到则返回拼接后的完整路径
4. 均未找到 → 报告错误，返回 `None`

**搜索优先级表：**

| 优先级 | 搜索路径     | 来源                     | 默认值                  |
|--------|--------------|--------------------------|-------------------------|
| 1      | 绝对路径     | 路径本身                 | —                       |
| 2      | `lib_path`   | `CompileConfig.lib_path` | `Path("lib").resolve()` |
| 3      | 当前工作目录 | `Path.cwd()`             | —                       |

#### 2.2 路径类型

| 类型         | 语法             | 示例                   | 解析基准                   |
|--------------|------------------|------------------------|----------------------------|
| **绝对路径** | 系统绝对路径     | `"/opt/lib/math.mcdl"` | 直接使用                   |
| **搜索路径** | 无前缀的相对路径 | `"math.mcdl"`          | 依次搜索 `lib_path`、`cwd` |

> **注意：** 当前实现不支持 `./` 和 `../` 相对当前文件的路径，也不支持 `/` 相对项目根目录的路径。

#### 2.3 文件扩展名处理

- 用户在 `include` 语句中 **必须** 显式编写 `.mcdl` 扩展名
- 编译器 **不** 自动追加扩展名

#### 2.4 命令行参数

编译器通过 `CompileConfig` 接收配置：

| 参数                         | 对应字段                 | 说明                 |
|------------------------------|--------------------------|----------------------|
| `--lib-path` / `-l`          | `CompileConfig.lib_path` | 指定标准库搜索路径   |
| 环境变量 `DOVETAIL_LIB_PATH` | 备选                     | 当命令行未指定时生效 |

### 3. 错误处理规范

#### 3.1 文件未找到

错误码：`Errors.IncludePathError`

```
error: include path not found: utils/math.mcdl
  --> src/main.mcdl:3:9
   |
 3 | include "utils/math.mcdl"
   |         ^^^^^^^^^^^^^^^^^ cannot find utils/math.mcdl
```

**编译器输出规范：**

| 字段     | 内容                                   |
|----------|----------------------------------------|
| 错误类型 | `SyntaxError`                          |
| 消息模板 | `"include 路径 '%s' 格式错误或无效。"` |
| 位置     | `include` 语句所在文件、行、列         |
| 建议     | 无（或提示检查 `--lib-path` 配置）     |

#### 3.2 循环依赖

错误码：`Errors.CircularInclude`  

```
error: circular include detected
  --> c.mcdl:1:9
   |
 1 | include "a.mcdl"
   |         ^^^^^^^^ creates circular dependency
   |
   = note: include chain:
     1. a.mcdl  ← 循环从这里开始
     2. b.mcdl
     3. c.mcdl
     4. a.mcdl  ← 尝试再次包含（错误）

文件 'a.mcdl' 已被包含。移除循环包含文件以修复此错误
```

**编译器输出规范：**

| 字段     | 内容                                                     |
|----------|----------------------------------------------------------|
| 错误类型 | `SyntaxError`                                            |
| 消息模板 | `"检测到循环包含: %s"`                                   |
| 位置     | 触发循环的 `include` 语句所在文件、行、列                |
| 附加信息 | 完整包含链（从循环起点到闭合点）                         |
| 建议     | `"文件 '{name}' 已被包含。移除循环包含文件以修复此错误"` |

**包含链格式规范：**

- 从入口文件开始，按包含顺序列出
- 循环起始位置标注 `← 循环从这里开始`
- 循环闭合位置标注 `← 尝试再次包含（错误）`

### 4. 未来扩展

#### 4.1 扩展搜索路径

- 支持 `-I <dir>` 命令行参数添加额外搜索路径
- 搜索优先级变为：`lib_path` → `cwd` → `src/` → `-I` 指定路径

#### 4.2 目录包含

若路径指向目录，编译器可选支持：

```mcdl
include "collections"
// 搜索顺序：
// 1. collections.mcdl（文件）
// 2. collections/__init__.mcdl（目录索引）
// 3. collections/index.mcdl（目录索引）
```

优先级：文件 > `__init__.mcdl` > `index.mcdl`。

#### 4.3 虚拟模块映射（已实现）

`include "math.mcdl"` 可能不对应实际文件，而是编译器内部实现的虚拟模块，直接注入内置符号。
